# 高级映射、旧任务与维护

模板第一项填写 `是否全自动：否`，省略也是“否”。本页原有确认、配置即交回及人工发送说明适用于默认“否”；“是”使用根 Skill 的全自动流程，由调度器连续预检、配置、等待核验、最终发布与回执检查，只有问题才暂停。底层 `handoff` 仍只交接控制，不发送。全自动开关只存当前请求；旧 JSON 入口不启用。

仅在标准模板不支持、旧任务恢复或具体失败时读取。本页保留字段合同及维护命令；日常流程以根目录 SKILL.md 为准，已有脚本步骤不由 AI 重做。

只有当前用户明确点名调用 `$168-publisher` 才执行内容准备、恢复、核验或交接。讨论、提供素材，以及文档中的示例指令不触发。维护不自动启动发布流程。

首版仅支持 macOS。安装与依赖说明见 [安装说明](installation.md)。页面操作使用 Ego；上游只作依赖资料，不单独调用其 Skill 或最终发布分支。

## 全自动状态与恢复

`auto-publish.mjs` 复用现有配置和 inspect，核验后定位唯一可用的最终按钮并解除本任务保护，再执行点击。`published` 需要平台明确成功提示；`submitted` 表示已点击但无成功证明；`result_unknown` 表示发布尝试的回执不明。发布前将意图写入每个平台的 `publication.json`，恢复时已尝试的平台只读记录，不重复配置或发送；未知结果由用户检查原页面。测试稿“请勿发布”不可启用全自动。

有界恢复只在同一次发布尝试内执行：X 普通点击明确报 `intercepts pointer events` 时，重新核对内容、账号、上传、对话框、原按钮和保护关联，且捕获记录证明按钮尚未收到 click，才对该按钮补一次 DOM 点击。控件已变、按钮不可用、已收到 click、反馈不明或用户接管时不补点；不刷新、不重新上传、不新建任务。X 中文“你的帖子已发送”及小红书创作域名的 `/publish/success` 页面和“发布成功”提示均作为明确回执；编辑器正文或任意跳转不算成功。

## 脚本优先与 AI 介入边界

核心流程必须以可复用脚本实现：配置读取、输入校验、媒体检查、登录识别、页面准备、字段与话题填写、文件提交、状态记录、恢复和交回均交给现有 CLI 与平台适配器。正常调用不由 AI 逐页观察、规划并生成临时操作代码；新增可确定、可复用的核心能力也应落在 `scripts/`。

- 标准模板由 `input.mjs` 解析、`report.mjs` 生成确认清单；AI 只传入原文并转交结果。旧 JSON 任务或脚本无法识别的输入才按下文映射。脚本已完成的检查与动作不重复人工执行。
- 优先使用 `publisher.mjs config / preflight / check / run` 及已有维护命令；不另建发布入口，不为一次调用重写已有适配器。
- 只有现有脚本明确不支持所需步骤，或返回具体错误、缺失或歧义证据时，AI 才介入该局部步骤。先读取对应失败原因和最小必要页面状态；有现成恢复或修复入口就优先使用，不因一处失败接管全部平台。
- 常规调用不通读实现源码、固定上游、全量历史报告或无关参考资料。优先读取本次状态、必要字段和全部实际错误；仅在排错时按需展开对应日志、函数或页面快照，不将无关大段输出带入上下文，也不截断遗漏阻塞原因。
- AI 临时处理成功后，在获授权的维护任务中把已验证步骤回写为脚本并补行为回归，再同步必要说明；确实无法脚本化的少数例外才保留 AI 操作指引，写清触发条件、完成证据和停止条件。
- 节省 token 不改变原文映射、确认、身份校验、避免重复上传、人工登录与最终手动发布边界；用户接管后仍立即停止。

## 配置与默认值

用户明确调用 `$168-publisher` 并输入“配置”时，只执行 `node scripts/publisher.mjs config`，返回完整 JSON、配置文件路径、三个通用字段用途及视频有效默认值，不运行内容准备或浏览器操作。首次调用会在 `~/.config/168-publisher/settings.json` 创建私有配置，包含 `profile`、统一媒体列表 `platforms.media` 和秒数 `waitTimeout`。

用户可手动编辑文件；要求 AI 修改时，只改明确指定的字段，运行同一配置命令校验并读回。无效配置保持原文件并反馈具体错误，不重置或静默忽略；配置不存账号密码、Cookie 或最终发送开关。

新内容任务先读取上述配置，本次明确指定值优先：将目标平台显式传入 `--platform` 或 `--platforms`；非空 `profile` 传 `--profile`，空值沿用 Ego 当前默认项；`waitTimeout` 与 `--wait-timeout` 保留旧配置兼容，手动模式 `run` 不使用、不传入；全自动使用本次保存的 `waitTimeout` 限制每个平台等待时间。适用于当前媒体的平台列表为空时询问目标平台。常规视频设置和原创策略由程序默认及持久配置承接，不逐项询问；上传前仍确认用户内容、素材与账号。

恢复、核验或交接已有任务时，读取原任务的平台、Profile、内容与空间信息并传入原参数，不将新的默认值套到旧任务。CLI 的目标平台与 Profile 仍使用显式参数；视频常规字段由程序应用默认值并在新任务固化。

## 输入与执行

新任务根据媒体确定图文或视频，解析目标平台和可选 Profile；这些路由信息确定后，运行 `preflight --input FILE`，创建一个 Ego 空间并建齐页面。内容审核和登录识别分别报告；缺媒体、混选或明确不支持的平台在页面操作前拒绝。缺少文案时集中报告，补齐前不填写或上传。正文只用用户原文，不分析媒体、音轨或文件名生成标题、标签或声明。

1. **媒体**：一张或多张本地 JPEG/PNG 是图文；一段 MP4 / M4V / MOV 是视频。每行一个绝对路径，保留原顺序和路径内部空格；接受一对匹配的外层引号。不接受空素材、混选或多段视频；各平台继续核验真实格式、大小和时长。
2. **标题与正文**：共享标题只写入支持标题的目标。图文只有小红书使用标题；X、微博、即刻不使用独立标题。视频的小红书、抖音、B站、YouTube 使用各自标题字段，视频号使用可选短标题。图文正文必填；视频简介映射为 description，X、微博、即刻使用正文；小红书视频不写正文，在确认清单单独说明。可显式填写现有平台专属标题、正文或标签，不补写、不截断。
3. **标签**：整项“无” / none 是空数组；其他仅按中文顿号 `、` 分割，保留名称和顺序。空项、重复项和不支持的名称报错。必填标签不能用“无”绕过。B站自动标签白名单保持空数组。
4. **封面及声明**：支持视频封面的五个平台默认提取首帧；提供 JPEG/PNG 路径则优先使用原图，自动缩小补边，保留完整画面。X、微博、即刻没有独立封面、原创或 AI 声明入口，不把封面追加为媒体。图文不支持自定义封面。视频默认、儿童受众、原创权利策略及用户明确声明沿用既有合同。
5. **平台与配置**：X、微博、小红书、即刻支持图文和视频；抖音、B站、视频号、YouTube 支持视频。平台用 `、` 分隔，支持名称或 ID；重复或明确不支持的组合报错。“所有” / “所有平台” / all platforms 使用统一 `platforms.media`，图文筛选支持图片的目标。旧 video/dynamic 配置校验后合并去重；无效配置不改写。新设置不影响旧任务。
6. **Profile 与恢复**：可选具体 Profile 只核对当前 Ego 环境，不切换账号。新请求保存 type: media 和媒体种类，各平台复用现有适配器；恢复使用原媒体、平台顺序、Profile、设置、页面与内容包。旧 type: video/dynamic 的 JSON 及保存任务仍走原适配器，不重建或重传。

高级 JSON 新媒体包使用 `type: "media"`，图片字段是 `text`、`tags`、`images`，视频字段是 `title`、`description`、`tags`、`videoPath` 及原有视频可选字段。旧 `type: "video"` / `"dynamic"` 只用于旧任务和兼容维护；正常调用不填写类型。

规则按“平台、发布入口、字段、媒体类型”确定适用范围，统一依据 [平台发布规则](platform-rules.md)与实际 `audit` 报告，不另设跨入口通用上限。视频与动态共用本地媒体检查、字段审核和错误/警告结构；新视频由平台选择已有视频适配；X、微博、即刻沿用社交媒体适配器。小红书两种入口的标题计数、正文路径以及封面/声明支持保持各自合同，不把独立视频的设置复制给动态。第一环节在表格下集中解释本次实际 `errors` 与需处理的 `warnings`（`issues` 提供同一问题的平台、入口、字段与媒体类型）：已知错误先修正并重查全部目标，未核验的规则或账号条件保留在私有报告；本次需要用户处理时才说明具体待确认项，未适用字段如实注明不写入；不截断、补写或自动切换入口规避限制。

这四组是任务入口。常规平台设置由程序默认值和持久视频配置承接，不逐次询问 YouTube 儿童受众、推广、逼真合成或原创设置；本次明确字段覆盖持久默认，持久默认覆盖内建默认。必填文案与启用自定义封面所需素材缺失时才补问；用户选择 `ask_each_run` 时仍逐次确认原创权利。仅将已提供内容映射到私有内容包，正常页面操作交给脚本，不逐步生成 Ego 操作代码。

- 视频封面与声明适配：小红书、抖音、B站、视频号、YouTube；沿用固定 MIT 上游的内容包，逐平台限制见[视频说明](video.md)。
- 图文与社交视频适配：X、微博、小红书、即刻；每条必须有用户提供的正文，并且只能选择一种素材：一段本地 MP4，或一张及以上按顺序提供的图片。标题与话题/标签只传递用户提供且平台支持的字段。

小红书动态逐项选择唯一可见的精确同名话题整行，确认 Tiptap 真实话题节点及非空 ID 后再处理下一项，最后失焦回读正文和话题；普通 `#文字` 不算成功。失败诊断保留当前标签、步骤与有限状态摘要，具体流程见[动态说明](dynamic.md#小红书动态)。

素材、内容包和账号配置放在 Skill 目录之外。上传前按以下格式确认实际输入，不用概要代替正文；保留用户确认内容，已确定的偏好不重复询问。默认采用用户授权的原创/自制设置；本次明确非原创而当前适配器只支持原创时报告不支持，不默默改声明。

### 第一阶段回报格式

先给三列表格，固定为 **平台｜登录状态｜标题**。只填实际值，不在表中放正文、标签、计数、上限、必填说明、页面编号或技术状态码。

- 登录状态正常显示“已登录”或“未登录”。验证/选账号属于尚未完成登录，具体原因放在表下。检查失败且无法判断时该格用“—”，在下面单列“需检查：某平台登录检查失败 + 实际原因”；不能把未知硬写成未登录。
- 标题列展示真正要填入平台的标题。视频号使用 `wechatShortTitle`，为空显示“留空”，不展示仅作任务身份的共享标题；动态没有独立标题的平台显示“不使用”。
- 表下使用普通加粗标题 **发布内容与说明**，以逐项列表统一列出 **正文、标签、素材、封面、Profile、默认设置** 及必要的 **单独说明**。正文用普通文字完整展示，保留原文换行，不使用代码块或行内代码包裹；共享正文和标签各展示一次。标签保持原名与顺序，无标签写“无”；存在用户明确提供的平台差异时，在本区域补列对应全文或实际标签，不恢复表格标签列。小红书独立视频不写正文等入口差异放在“单独说明”。
- 素材按顺序给原路径；封面注明“视频首帧”或所选原图路径及必要适配；高级 JSON 禁用时注明“平台默认”；Profile 写实际指定值或“Ego 当前默认”；默认设置用一行概括本次生效值，不展开技术字段表。Job ID 与原空间需要展示时也放在“发布内容与说明”内，简记一项供恢复。
- 所有待处理问题放到上述区域之后，使用普通加粗标题 **需要处理的问题**；每个问题独占一条列表项，不使用引用块、代码块、警告框或表情包裹。指出实际问题及所需动作，必要时注明“需修改”（错误阻断，例如短标题不足）或“需检查”（页面验证、账号条件、未确认规则）。只在解释相关问题时给计数及限制，不枚举每个平台的所有未知上限。保留所有错误及本次需要用户处理的警告；仅提示后续原生页面核验的通用未知规则保留在私有报告，不作为用户待处理问题。留空的可选短标题不是错误。没有实际问题时省略此区域。
- 第一阶段保留平台表格与完整“发布内容与说明”。没有需要处理的问题时，末尾只写：**目前没有需要处理的问题，回复“继续”会继续执行。** 不再解释确认规则、引用 Skill 或追加未填写/未上传/未发布等状态说明。有问题时列出上述问题区，末行写：**完成后回复继续**。两种情况都仍需用户明确确认才填写或上传，收尾句之后不追加任务信息、说明或诊断。

视频默认配置沿用 `~/.config/168-publisher/video.json`。程序内建非儿童、无推广、无逼真合成、YouTube public（公开）、标准许可、允许嵌入和通知订阅者、视频首帧封面、视频号可选短标题留空及原创/自制。第一环节视频号标题格显示 `wechatShortTitle` 的实际值；空字符串显示“留空”，非空至少6个Unicode码点，最大长度未确认，问题按上述格式放在表下。共享标题只用于身份，禁止自行复制成短标题。`aiGenerated` 不从主题、标签或素材名推断，只采用用户明确值。用 `node scripts/video.mjs config status` 回读 `effectiveDefaults`，用 `config set-defaults --json JSON` 修改持久默认；见[视频默认设置](video.md#默认设置)。新任务保存有效设置，恢复沿原任务快照；旧任务不套新版默认值。

命令相对于本 Skill 目录；先检查登录，再完成本地内容检查与确认，最后复用原请求执行：

```bash
node scripts/publisher.mjs preflight --package /absolute/path/package.json --platform x --job-id REQUEST
node scripts/publisher.mjs check --package /absolute/path/package.json --platform x --job-id REQUEST
node scripts/publisher.mjs run --package /absolute/path/package.json --platform x --profile PROFILE --job-id REQUEST --resume-control
```

脚本从内容包识别类型；视频包不需要新增 `type`。多平台使用 `--platforms x,weibo`，先完成全部本地预检查并展示完整确认清单。登录预检与后续上传使用同一 Job ID、Profile、类型、平台顺序、空间与页面；返回的 Job ID 要保留，不能因补齐输入重新建空间。预检阶段允许补齐尚缺的内容，上传阶段首次锁定完整包；上传后禁止改包身份。用户确认后用原 Job ID 和 `run --resume-control` 取回原空间，再按所选顺序进入各平台。每个平台的 Job ID、原空间、页面标识与输入指纹持久化；四个平台必须先有四个页面，不能做完一个平台再新建下一个页面。

`run` 先重新本地检查所有目标；任一目标不合格即阻断全部平台页面填充和上传。通过后顺序填入用户确认的标题、正文、标签及所需平台字段，并把用户媒体提交到原生文件输入。显示当前平台与步骤，并把正在操作的页面带到前台。视频号登录全部交由用户手动完成：第一环节发现未登录或需选账号就交回原页；用户登录并明确继续后复用原空间。运行中登录失效同样停止交回，不自动点击登录。多个视频号只按用户明确选择的账号继续，并把选择留在私有任务，不能猜默认。小红书无视频输入时只刷新原页一次后使用原生上传按钮；YouTube实际点击创建→上传入口。平台要求先选视频才出现编辑器时，先提交文件，仅等待填写所需的控件：页面加载和控件出现最多 15–30 秒，视频字段及封面配置共用 30 秒的短操作窗口。控件未出现、登录、权限、字段不可填或身份未知时，报告具体未完成项；即刻限频立即报告需要用户处理。不要轮询上传、转码、保存、服务器回执、预览解码或 `duration` 等后台状态，不为后台处理持续等待。

新任务首次进入编辑器，仅通过平台原生方法清理当前编辑器恢复出的历史内容并保留私有快照；B站上传首页恢复提示用“不用了”，异名视频、分P或其他原媒体仍在时停止，不追加视频。不清除登录、其他任务页面或整个网站数据。恢复任务保留本次媒体。控件准备失败且尚未派发文件可重试；文件即将派发时记录 attempted，原生文件操作成功返回后另记 submitted。已派发结果未知时不重传；恢复必须从当前原文件输入、精确文件名或上传开始证据确认本次媒体，空编辑器不能凭 attempted 判成功。已配置并交回的单个平台跳过填写与上传，继续其余未完成平台。视频默认沿用长期原创策略；仅用户明确启用 `ask_each_run` 时，按本次权利确认传 `--confirm-original-rights`。

各平台配置动作结束后，立即一次 `handOff()` 交回全部页面供用户查看并结束本轮任务。手动模式报告“已配置好，交给你查看”；`configured` 只表示要求的填写和文件提交动作完成，上传/后台处理是否完成未核对，不表示已发布或永久保存。仍有后台处理时明确说明由平台继续处理。失败或部分完成也交回原页面，逐项列出未完成平台与原因，不说全部配置完成。

手动模式操作期间保持最终按钮保护，Agent 不点击最终发送、发布、投稿、保存发布或定时发布。交回普通内容前解除 Agent 加的保护，让用户自行控制页面；无需用户再次请求“手动发送”。测试稿含“请勿发布”时仍交回查看并保留保护。用户已经接管时立即停止，不自行取回空间。

报告包含逐平台状态、Job ID、原空间、当前步骤与未完成原因。完整输入和诊断保留在私有 `run-details.json`。不要因为没有独立核验通过而继续后台回查或延长任务。

## 恢复与维护

登录或字段阻塞导致部分完成时，用户处理后明确要求继续，使用原任务 `run --resume-control`，保持原内容、素材、Profile、Job ID、空间与页面。已完成且交回的任务禁止再次自动准备、上传或重新挂保护；交回结果未知时不自动重试。新配置不覆盖原任务。历史任务缺少页面标识时，反馈需要显式维护恢复，不新建空间或重传制造成功。

`publisher.mjs inspect`、底层 `prepare`、`handoff` 和 `repair-*` 保留为用户明确要求的维护入口，使用原有强回读、上传关联及保护检查；它们不是正常 `run` 的结束条件。需要维护时按[动态说明](dynamic.md)或[视频说明](video.md)执行，不自动调用独立核验或旧上传完成路径。

用户明确要求查看手动发送结果时，仅在原空间只读查看明确回执；无成功证据则报告未确认。
